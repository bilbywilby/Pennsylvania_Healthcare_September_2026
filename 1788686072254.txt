## Blocker: the synthesized-SERFF default breaks the alias test

`load_filings_from_csv` defaults a missing `serff_id` to `"SE-000000000"` — which then **fails** `SERFF_REGEX` (needs 4 uppercase letters, this has 2). So `test_legacy_column_names_are_normalized`, whose legacy extract has no serff_id column, will raise instead of returning records. Backward compatibility — the `backward_compatible_fallback: true` promise — is broken by an arbitrary default. Patch it before writing tests:

```bash
python3 - << 'FIXEOF'
from pathlib import Path
p = Path("scripts/schema_reconciliation.py")
t = p.read_text()
assert 'import re\n' in t and t.count('import zlib') == 0
t = t.replace('import re\n', 'import re\nimport zlib\n', 1)
old = '(row.get("serff_id") or "SE-000000000")'
assert old in t
t = t.replace(old, '(row.get("serff_id") or "")')
anchor = '            if not carrier:\n                raise FilingValidationError(f"Row missing \'carrier\'/\'serff_id\': {row!r}")'
assert anchor in t
fix = '''            if not carrier:
                raise FilingValidationError(f"Row missing 'carrier': {row!r}")
            if not serff_id:
                serff_id = "SYNT-%09d" % (zlib.crc32(carrier.encode("utf-8")) % 10**9)
                logger.info("Synthesized SERFF ID %s for legacy row (carrier '%s')", serff_id, carrier)'''
t = t.replace(anchor, fix)
p.write_text(t)
print("[OK] patched: per-carrier synthesized SERFF for legacy rows")
```
