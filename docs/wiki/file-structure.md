# File Structure

The repository separates public evidence, generated outputs, operating code,
and explanatory material so readers can tell what they are looking at.

| Path | Role | Important boundary |
| --- | --- | --- |
| `data/public/` | Checked-in public datasets and generated crosswalks | No private household or claim data. |
| `data/private/` | Local working outputs and anomaly files | Git-ignored; do not publish contents. |
| `docs/wiki/` | Plain-language public reference pages | Every durable page needs sources and status labels. |
| `docs/` | Technical appendices and source-reliability records | Holds methodology and unresolved evidence notes. |
| `01_` through `06_` scripts | Ordered validation and provenance pipeline | The pipeline stops at the first failed stage. |
| `pa_audit_tui.py` | Terminal front door | Runs health checks, the pipeline, and wiki search. |
| `README.md` | Project overview and command reference | High-level orientation, not a consumer quote. |
| `approved_rates_2026.csv` | Root-level source candidate currently present | It is not automatically the same as the pipeline's public input. |

## Public Data Rules

Put only sourceable, non-sensitive material under `data/public`. Keep
household-level information out of the repository. A new dataset needs a
schema description, source URL, checked date, and provenance note before it is
treated as a source of truth.

## Generated Files

The county crosswalk is generated by `02_crosswalk.py`. Do not hand-edit it to
resolve a mapping disagreement; correct the owning definition and rerun the
validation stage. The current pipeline also expects specific carrier and
termination inputs documented by `05_ingest_carrier_extensions.py`.
