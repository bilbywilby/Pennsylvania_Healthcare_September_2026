# Public Resource of Truth: Architectural Framework

This document defines the methodology for transforming local, heterogeneous audit repositories, scripts, and dataset extracts into an exhaustive, public source of truth.

---

## 1. Core Principles

To achieve public trust without relying on centralized authority, the workspace operates under four architectural mandates:

1. **Atomic Script Isolation:** Every pipeline operation is broken into single-responsibility, idempotent shell scripts. If any stage fails, it leaves no corrupted state behind.
2. **Cryptographic Provenance:** Every artifact (dataset, script, log, schema definition) is fingerprinted via SHA-256 hashes ($H(x)$) and bound to a signed Git commit hash.
3. **Strict Schema Boundary Enforcement:** Raw extracts and intermediate outputs are checked against hard contracts (`HANDOVER.json`). Malformed or unverified rows trigger immediate pipeline halts.
4. **Deterministic Static Publishing:** Public deliverables are emitted as static Markdown, JSON, and CSV artifacts that can be audited using standard POSIX utilities (`sha256sum`, `jq`, `diff`).

## 3. Data Lineage & Watermarking Standard

Each public record generated by the pipeline must encode its calculation basis and verification state:

$$\text{Record State} = \begin{cases} \text{Verified (Covered Lives Weighted)}, & \text{if } \forall i, v_i = \text{True} \land b = \text{covered\_lives} \\ \text{Unverified / Fallback}, & \text{otherwise} \end{cases}$$

- **`weighted_rate_change`**: Weighted mean calculated as $\bar{r} = \frac{\sum (r_i \cdot l_i)}{\sum l_i}$, where $r_i$ is the rate change and $l_i$ represents covered lives.
- **`verified`**: Boolean flag set to `True` if and only if all underlying carrier filings are cryptographically and administratively verified.
- **`basis`**: Explicit string output (`covered_lives` or `unweighted_fallback`).

## 4. Termux / POSIX Environment Guidelines

Because operations run in lightweight POSIX environments (including Termux/Android shell):
- Avoid heavy runtime dependencies where native standard tools suffice.
- Use `jq` for JSON manipulation, `awk`/`sed` for stream transformations, and standard Bash array primitives.
- Ensure all file paths remain relative to the project root directory.
