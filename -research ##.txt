# 1. Regulatory & Data Landscape

A Pennsylvania-focused audit pipeline must align with federal and Commonwealth transparency and privacy regimes.

## 1.1 Federal Framework

### ACA Transparency & Rate Review

Under the Affordable Care Act (ACA), insurers must submit rate filings and justification documents for review. These are typically published via:

* State insurance department portals
* SERFF (System for Electronic Rate and Form Filing)
* Public rate review portals

The **Centers for Medicare & Medicaid Services (CMS)** oversees rate review standards and marketplace operations.

### HIPAA & Data Security

Although public filings generally avoid PHI, audit pipelines must assume potential PII presence in:

* Complaints
* Actuarial memos
* Supporting exhibits

Relevant oversight:

* **U.S. Department of Health and Human Services (HHS)**
* HIPAA Security & Privacy Rules

Implication:
Even if ingesting public records, the system must treat extracted personal data as potentially sensitive.

# 2. Architecture Research & Best Practices

## 2.1 Ingestion Design Patterns

### Idempotent Ingestion

**Recommended Model:**

* SHA256 checksum on raw artifact
* Unique ingestion_key (source + source_id + version)
* DB unique constraint
* Write-once S3 storage

### Crawl Strategy

| Method            | Use Case                | Risk               | Mitigation                        |
| ----------------- | ----------------------- | ------------------ | --------------------------------- |
| Scheduled polling | Static portals          | Missed updates     | Delta comparison                  |
| Sitemap parsing   | Structured filing sites | Layout changes     | Schema validation                 |
| Headless browser  | JS-heavy portals        | Anti-bot detection | Rate limits + user agent rotation |

Use exponential backoff and jitter.

---

## 2.2 Extraction & OCR Research

### PDF Parsing

Libraries:

* pdfminer
* PyMuPDF
* Tesseract OCR

Challenges:

* Scanned actuarial tables
* Multi-column layouts
* Embedded images
* Watermarks

Mitigation Strategy:

* Page classification before extraction
* Table boundary detection
* Hybrid rule-based + LLM extraction fallback
* Confidence scoring per field

### Extraction Accuracy Benchmarking

Establish:

* Precision/Recall on structured fields
* Character error rate (OCR)
* Table reconstruction accuracy

Target:

* > 95% document extraction success
* > 90% structured field precision

# 3. Semantic Enrichment & Vector Strategy

## 3.1 Embedding Strategy

Embedding use cases:

* Similar rate justification detection
* Cross-filing anomaly detection
* Complaint clustering
* Enforcement pattern detection

### Indexing Options

| Engine              | Strength     | Tradeoff        |
| ------------------- | ------------ | --------------- |
| pgvector            | Simple infra | Scale limits    |
| RedisVector         | Fast         | Extra infra     |
| Dedicated vector DB | High scale   | Cost/complexity |

For MVP: pgvector inside PostgreSQL.

### Index Configuration

* ivfflat or hnsw index
* Periodic reindex on corpus growth
* Store embedding_version for future model upgrades

* Investigator relevance scoring

* Periodic embedding recalibration

Metrics:

# 4. Security & Compliance Hardening

## 4.1 Encryption Strategy

* TLS everywhere
* KMS-managed encryption keys
* Encrypted S3 buckets
* Encrypted Postgres volumes
* Secret rotation every 90 days

## 4.2 Audit Logging Requirements

Log categories:

* Ingestion events
* Extraction steps
* User access events
* Search queries (PII redacted)
* Report exports

Store logs in append-only audit table.

## 4.3 Disaster Recovery

Recommended:

| Component  | Backup Strategy        | Frequency  |
| ---------- | ---------------------- | ---------- |
| PostgreSQL | PITR enabled           | Continuous |
| S3 Buckets | Versioning + lifecycle | Continuous |
| Redis      | Snapshotting           | Hourly     |
| Kubernetes | IaC recreation         | On demand  |

Conduct restore drills quarterly.
